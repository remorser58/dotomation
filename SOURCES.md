## Operating sources

The live-record protocol, the host placement and the VM recovery procedure are ports of the owner's own operating material, not upstream OMP text. The live record is codified from records in use on 2026-11-22 in the shared Dots folder on `local`, `<work root>/.dots-ops/`. The recovery procedure is a procedure-only port of the operator's own watchdog kit on `local` (`RECOVERY.ko.md`, `PURE-REPLAY.ko.md`, `CANARY.ko.md`, `TOOLCHAIN.ko.md`, `REV-OPERATIONS-HANDOFF.ko.md`), whose `recovery.py` is pinned at SHA-256 `9aa963419b668c0b8f3924bdedba21b7fe62332329bba52978667c381f4042a3`. That kit, its ledger and its Python are not redistributed here; this repository describes the procedure and references the pinned file. Connector names and the placement order come from owner direction.

The read-only monitor [`tools/dots_monitor.py`](tools/dots_monitor.py) is newly written for this repository at the owner's request and contains no upstream code. Its inputs are the owner's existing files: the live records above and the Web GPT Agent daemon `app.log` of each account a dot runs on, whose request-line format (`request POST mcp/core → 200 in 110ms`) was read from those logs on 2026-11-22. It depends on no package; `ssh` and the GitHub CLI `gh` are existing tools on the reader's machine.

The helper [`tools/dots.py`](tools/dots.py) is likewise newly written for this repository at the owner's request and contains no upstream code. It writes and reads only the shapes above ([mail-v1](protocol/mail-v1.schema.json), [live-record-v1](protocol/live-record-v1.schema.json), [memory-v1](protocol/memory-v1.schema.json)) plus the read markers, its own per-process `listen/` markers, self-driving multi-track loop contracts/states/events (`loops/<DOT>/*.contract.json`, `*.state.json`, `*.events.jsonl`), the optional `dots.json` and its own watchdog ledger (`watch/state.json`, or the path given with `--state`), the update stamp `<base>/.update-check.json`, and, when it updates itself from a release, its own file and a `dots.py.bak-<old version>` beside it; it depends on no package. Its watchdog `watch` reads the mail folders, the `listen/` markers, the `live/` lines (for `{dot}`), `dots.json`, `loops/<DOT>/` under `--keep-full`, and its own ledger. With `--keep-full`, it reads `roster.json` solely to account for free/parked/unassigned slots (falling back to live records when the roster is older than `--roster-fresh-min`, while `board` still treats roster claims as `(the root's claim)` and flags contradictions against mail/live evidence as `CLAIM-STALE`). Its wait-and-poll design follows the behaviour of the Web GPT Agent connector these agents already use — one command yields after at most 30 seconds and a later poll returns as soon as the command prints — which was observed on the owner's accounts on 2026-11-23, not taken from any upstream source. The watchdog takes its commands and delays from the owner's own command line first (and ignores `dots.json` hook commands unless `DOTS_TRUST_CONFIG_CMDS=1`), because `dots.json` sits in the folder the dot root writes.

Mode 2 (`tools/subdots.py`) and the zero-token single-repo pilot (`tools/dots_pilot.py` + `tools/dots-pilot.example.json`) are also newly written for this repository at the owner's request using Python 3.9+ stdlib only, with zero upstream code, zero personal AI tokens, and explicit owner-started lifecycles.
