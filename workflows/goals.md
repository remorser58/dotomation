# Goal and workflow operations

The operator executes these procedures through existing native Dots capabilities. Persist only in an already approved task record, not a new service or consumer-repo installation. Use an existing authorized goal if one matches; never reset a paused, cancelled or budget-limited goal to get around its state.

## 1. Goal card

Record: stable goal/work ID, revision, owner’s outcome and non-goals, current authorization/exclusions, acceptance criteria with evidence classes, exact inputs, owners and reviewers, dependencies (no cycles), remaining attempt budget, pending effects and the next decision. On resume, read the actual artifacts/receipts and reconcile against the current revision, not a stored “done” string. Distinguish a durable record from this single conversation. If durable state is mandatory but no approved writable space exists, stop that gate.

For a clear request move to planning/execution. For **WISH** first name the audience, present pain, desired change, observable success, constraints, permission boundaries and assumptions. Ask only for an uncertainty that would change a consequential action or outcome. Independent authorized investigation can continue; silence, an answer from another agent and a sample plan cannot grant consent.

## 3. Existing ULW / WISH gate adapter

If ULW/WISH was requested and the corresponding existing skill is exposed, open that actual skill AND its goal and contract references. Its required tools and authorized storage, not this Markdown, decide native gate status. Never install a new checker or copy one into the consumer repository just to produce a PASS.

1. Prepare the actual goal DAG and each child's contract against goal revision, plan and upstream receipts. Specify applicable evidence classes (unit, integration, static, UI, native, provider-live, document, synthetic) and the actual permission required for each.
2. Freeze all affected inputs, candidate and contract at one version. Capture genuine commands/results or direct observations with check ID, evidence kind, locator, date/attempt, tested count and failures/skips/not-run where applicable. A status of zero and a screenshot cannot prove a provider call, complete suite, or native GUI. Record prior unrelated failures separately.
3. Require a real independent reviewer (neither coordinator nor implementer for this native ULW/WISH gate). Have them inspect the actual candidate, checks, raw evidence, completeness, approvals and unresolved issues. Preserve their own receipt. A second role label for the same writer does not count.
4. If already available and permitted, run the skill's child gate, accept its successful child result into the current goal, then run its goal-completion check immediately before claiming the whole goal. The original gate's blocked exit is a blocker; one accepted child is not a completed goal. After any related change, rebind current evidence and invalidate downstream receipts. Never substitute this repo's synthetic examples or a human checklist for the native result.
5. If a native checker is unavailable, report NATIVE_GATE_NOT_RUN and the exact missing capability. For a task whose contract requires that checker, overall status is BLOCKED. For a separately scoped manual review, name it as manual (for example VERIFIED_SCOPE: document contents) and state what was not proven. A textual goal is not cryptographically bound or host-enforced.
6. A user correction or source revision can invalidate both tests and review. Preserve history, never weaken criteria, and cap retries at the prior authorized budget (the existing ULW/WISH contract allows 1–5 attempts). On interruption report already-applied effects and future actions separately. Never promise an automatic wake or continuation unless an existing and authorized native mechanism actually provides it.

**Return one decision:** PLAN_READY / EVIDENCE_COLLECTED / VERIFIED_SCOPE (state mechanism) / BLOCKED / PAUSED / CANCELLED. Use “native ULW/WISH gate passed” only for actual native receipts. Always state the exact immutable result and remaining limits.
